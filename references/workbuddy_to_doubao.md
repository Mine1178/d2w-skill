# WorkBuddy 指挥豆包操作手册

> 你是 WorkBuddy，想让豆包帮你干活？按这个手册来。

## 核心原理

豆包没有常驻进程，**不会自动看邮箱**。你需要：
1. 把任务写成文件放到指定目录
2. **告诉用户**让豆包去读这个目录
3. 豆包处理完把结果写到另一个目录
4. 你读结果文件

## 操作步骤

### 1. 写任务文件

路径：`<项目目录>/inbox/tasks/NNN_任务名.md`
（NNN 是三位序号，从 001 开始递增）

文件格式：
```markdown
# 任务：<简述>

## 要求
<具体要求，越详细越好>

## 验收标准
<怎么算完成>

## 输出位置
<结果写到哪里>
```

### 2. 告诉用户触发豆包

任务写好后，**直接对用户说**：

> 任务已写到 inbox/tasks/001_xxx.md。
> 请你打开豆包，说："看看 WorkBuddy 有没有给我派新任务"，豆包会自动读取并处理。

### 3. 等豆包处理完

豆包处理完会写结果到：
`<项目目录>/inbox/results/NNN_任务名.md`

### 4. 读结果

你读 `inbox/results/` 下的结果文件就行。

## 完整示例

**你（WorkBuddy）操作**：
```bash
# 1. 创建任务目录（如果没有）
mkdir -p 项目目录/inbox/tasks
mkdir -p 项目目录/inbox/results

# 2. 写任务文件
cat > 项目目录/inbox/tasks/001_写单元测试.md << 'EOF'
# 任务：给 utils.py 写单元测试

## 要求
- 覆盖 utils.py 里所有函数
- 边界条件都测到
- 用 pytest 框架

## 验收标准
- pytest 全部通过
- 覆盖率 > 80%

## 输出位置
结果写到 inbox/results/001_写单元测试.md
EOF

# 3. 告诉用户
对用户说：任务 001 已写好，请让豆包处理。
```

**用户对豆包说**：
> 看看 WorkBuddy 有没有给我派新任务

**豆包自动做**：
1. 跑 `python poll_tasks.py --cwd 项目目录`
2. 发现 001 号任务
3. 处理完写 `inbox/results/001_写单元测试.md`
4. 告诉用户处理完了

## 快速检查

你可以随时跑：
```bash
ls 项目目录/inbox/results/
```
看结果文件有没有生成。

## 注意事项

- 任务文件用 UTF-8 编码
- 序号递增，不要重复
- 任务要具体，别写"帮我优化一下"，要写"把 utils.py 的 parse() 函数性能提升 50%"
- 豆包处理时间取决于任务复杂度，小任务几分钟，大任务几小时
