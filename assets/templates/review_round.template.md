# review_roundN 模板 — 审核报告

> 用法：审核方每次审核后复制为 `inbox/review_roundN.md`（N = 现有最大轮次 + 1）。填空替换 `<占位>`。
> 核心要求：问题必须写清"现象 + 根因 + 修改方向"（让干活方能照着改）；验收标准必须可验证；
> 无 P0 时末行必须写 `STATUS: NO_P0`；评分表 5 维各 1-5 分（锚定标准见下方表格，5=完美，3=可用但有改进空间，1=不合格），
> 收敛线 = 实际评维数 × 4（非 GUI 项目界面维记 N/A 并从分母剔除）。

| **总分** | **<X>/<实际维数×5>** | 收敛线 = 实际维数×4 |

评分锚定（避免不同审核方口径不一）：

| 维度 | 5 分（完美） | 3 分（可用有改进） | 1 分（不合格） |
|---|---|---|---|
| 正确性 | 核心功能全过 + 边界场景也过 | 核心功能过，边界有瑕疵 | 核心功能不过 / 结果错误 |
| 可维护性 | 模块清晰、命名规范、有注释、零重复 | 基本分层但耦合/命名一般 | 一坨无结构、无注释 |
| 性能 | 秒级响应、占用低、高频不卡 | 可用但偶卡 / 占用偏高 | 明显卡顿 / 内存泄漏 |
| 安全 | 剪贴板/数据/路径全防护，异常不崩不泄 | 基本防护但有遗漏 | 有破坏性风险（删数据/泄露路径） |
| 界面 | 布局/字体/DPI/交互全达标（L 组全勾） | L 组大部分过，个别小瑕疵 | 遮挡/错位/文字截断（即 P0） |

> 界面维豁免：CLI / 后台 / 无 GUI 工具记 N/A，总分分母相应减 5；收敛线 = 实际评维数 × 4。
